# OpenBKN DSH 插件累计更新说明

更新目标：`@openbkn/dsh-business-context@0.2.0-rc.2-openbkn.0.2.0-7`。这是待发布的统一说明；截至 2026-10-06，npm 的 `latest` 为 `-3`、`rc` 为 `-4`，`-5/-6` 仅为开发候选，`-7` 尚未发布。

本文合并 GitHub 账户 **kalias** 已合入主线的功能、修复与交付改进，不按开发候选拆成多份公告。作者归属来自 GitHub commits 的 `author=kalias` 查询，完整清单见 [account-contributions.json](../evidence/answer-fidelity-20261006/account-contributions.json)。其他账户的基础实现不计为该账户的新增贡献；下列说明描述最终行为，后续纠正过的历史判断不作为现行功能。

## 用户可以看到的变化

- **诊断入口集中在 OpenBKN 面板内**：侧栏只有一个 OpenBKN 入口，面板右上角显示“诊断”。可以查看组件加载、CLI、登录、平台请求和 Context Loader 的检查结果，并下载脱敏 JSON 报告。
- **业务组件失败时仍可诊断**：业务的配置、导入或初始化失败不会一起移除诊断入口；诊断组件独立失败时，业务面板保留并显示诊断不可用。bootstrap 或共享文件损坏仍属于整包故障。
- **分类与恢复更准确**：区分配置、等待服务、TLS、网络、认证拒绝、平台响应结构不合法和 CLI 输出问题。观察按接口分别记录，某接口成功不会掩盖另一个接口的失败；解析和校验通过后才记成功，恢复保留此前失败代码。无法判断时显示证据不足。
- **首次登录提示修复**：支持 CLI 0.1.5 的未登录和未知过期时间输出，不再把它们一律判成插件故障。Windows 上经 DSH 的可执行文件解析机制寻找 CLI。
- **连接提示减少误导**：已知错误给出对应操作；未知连接/RPC 错误引导查看诊断，避免直接归因到 Token 或平台地址。非法、相对或非 HTTP(S) 的 `baseUrl` 在初始化之前拒绝，报告只指出 `configField=baseUrl`，不导出配置值。

## 业务问答与溯源

- **OpenBKN 0.1.5 契约适配**：跟随实际注册的 `search_capabilities`、`execute_tool` 和有作用域的技能接口；按工具 schema 校验绑定的 `kn_id`。未审核的新工具和本版明确排除的工具保持拒绝。
- **减少空 Interaction**：普通闲聊、澄清及无需平台访问的回合不会仅因会话已绑定就创建 Interaction；需要平台访问的回合使用受控生命周期及持有的 conversation id，失败/取消可能留下未闭合 Interaction 的限制仍保留。
- **绑定状态独立保存**：绑定不再写入宿主不支持的会话事件，改为 DSH_HOME 下的原子会话文件，使官方 Desktop 可以重载业务会话；fork 仅在继承日志达到绑定点时继承绑定，新建子 agent 不自动继承。并发绑定只发布最终胜出的网络能力配置。
- **分层业务溯源**：本地执行时间线、平台操作、业务上下文图、证据链分别展示和降级。平台拒绝或不披露不会让本地时间线消失。大操作记录的原始读取上限提升到 64 MB；超限提示说明真实上限，不再建议无效的 `maxResultBytes` 调整。
- **来源知识网络修复（#62）**：按各元素的规范 Trace 引用识别来源，混合网络逐元素保留，不按第一个元素或当前绑定猜测；未知或未披露的引用显示未定位。
- **供应链回答规则补齐**：要求精确匹配物料、区分标准交期和采购交期、说明字段/单位/来源；BOM 完整分页，逐项列单耗和库存并说明仓范围、预留、在途及空集口径；找不到对象后停止无关探索。规则属于模型指导，不能保证每次回答正确。
- **回答交付一致性校验**：对明确要求完整 BOM 明细的回合，把最终回答与成功工具结果的父子料行、层级、名称、单耗、库存、单位及无库存记录标记核对；物理源表名以工具披露为准。缺少列头时，在原 Interaction 关闭前要求从已保存内容或现有变量补齐一次；直接库存回退要求披露范围内记录数，区分“无符合条件记录”和“有记录、数量为零”。字段明确披露“可用库存已扣减预留”时，拒绝与之矛盾的转述，兼容 JSON 与默认 TOON 元数据。回答转述不一致时，在同一回合更正一次，再次不一致则以错误结束。原始输出和纠正过程保留。该边界校验披露内容的一致性，不证明工具计算本身正确，也不保证所有问题的自然语言事实正确。
- **可复核的评测材料**：保留真实问答和失败轮次，加入独立平台查询、BOM 逐行/单位核对、会话导出及脱敏回归。历史局部包三题通过与统一 CI 包的复测分别记录，不能只靠同一版本字符串合并判定。

## 安装与接口变化

目标宿主仍固定官方 DSH **0.2.0-rc.2**，支持直接安装插件，不要求修改官方 runtime。原 OpenBKN Runtime 归档已停用；这次只交付一个插件版本。

包内三入口为：

| 入口 | 作用 |
|---|---|
| 包根 | 最小 bootstrap，持续提供浏览器模块 |
| `@openbkn/dsh-business-context/business` | 原业务插件及业务值；业务 row 的 id 不变 |
| `@openbkn/dsh-business-context/diagnostics` | 独立诊断组件 |
| `@openbkn/dsh-business-context/types` | Remote 边界类型，只作类型导入 |

本轮采用**完全卸载旧插件后安装固定新包**，不要求旧版本就地升级验收。重装不意味着删除整个 DSH_HOME、CLI 凭据或会话。若保留旧用户 patch：只按 `id: openbkn-business-context` 覆盖可继续使用；含旧根 `name` 的匹配条件需删除该行，或改为 `name: '@openbkn/dsh-business-context/business'`。自行用代码导入业务值的使用者需改为 `/business` 子路径。安装器使用随包 patch，注册三 row；不要手写旧两 row 结构。

工具调用超时现在可配置，默认仍为 20 秒。提高插件超时不能修复平台执行结果落库失败或网关限时；本版没有承诺深层查询性能问题已解决。

## 构建与交付改进

累计统一 DSH/Node/pnpm 版本约束、兼容补丁和锁文件来源；修复 Windows 路径、命令 shim、审计及 CI 失败未正确传递的问题。npm 使用可信发布和来源证明，插件发布工作流可先做 build-only 彩排。打包审计递归覆盖 exports 条件树及 main/types，防止声明指向未交付文件。构建清理旧 hash chunk，避免把陈旧产物装进候选。

Windows 测试 helper 现吸收实际 Windows 复验的修正：配置写入 BOM-less UTF-8、桌面首次初始化顺序，以及清理前核验 PID、创建时间、Host 路径与端口归属。它们是测试工具改进，不是插件运行时功能。
