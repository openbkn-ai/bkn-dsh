# bkn-dsh 0.2.1 Release Notes

[中文](2026-11-01-021-notes.zh.md)

**Current release:** `@openbkn/dsh-business-context@0.2.1-rc.3-openbkn.0.2.1-2`

**Publication status as of November 1, 2026:** Formally released, with both npm `latest` and `rc` pointing to this version. These notes cover the 0.2.1 base release and revisions -1/-2; they do not describe every feature as newly added in -2.

This release improves login, business provenance and selection across views, adds CSV file delivery, and relaxes loading restrictions for newer DSH versions. Users can start authorization from the OpenBKN panel, see the result, and enter an authorized knowledge network for business Q&A.

## 1. Login and connection recovery

- **No manual CA configuration for private-platform login.** Start CLI login from the panel and complete official account authorization in a separate Chrome or Edge browser profile, without editing shell configuration or system-wide certificate trust.
- **Show the login result in the current panel.** After authorization and credential verification, the panel automatically displays the result and accessible knowledge networks. This fixes the panel remaining in a waiting state after authorization has completed.
- **Require fresh authorization when platform identity changes.** A change to the platform origin, observed IP or certificate requires another browser authorization. Ordinary access-token renewal remains with the official CLI.
- **Apply the authorization identity to subsequent connections.** Login, MCP, knowledge-network directory and provenance reads use the corresponding authorization identity, preventing an older connection from sending its credentials to a newly authorized platform identity.

## 2. Business provenance and evidence

- **Add native platform provenance views.** Use event chains, evidence chains and business context to inspect the execution steps, inputs, processing, sources and conclusions associated with an answer.
- **Improve selection across views.** Selecting an execution step, source or evidence node locates related content using relationships disclosed by the platform, reducing repeated navigation between views.
- **Fix incorrect branch linkage through shared inputs.** Selecting a query retains that branch's relationship scope; selecting an input shared by two queries still shows both queries.
- **Distinguish missing and exceptional states.** Separately present not-generated, not-recorded, unauthorized, temporarily unavailable and partial results, while retaining the available local execution timeline.
- **Preserve platform records faithfully.** Display platform `invalid` states and reasons verbatim and retain the original records. The plugin does not reassess their validity or invent evidence relationships.

## 3. CSV file delivery

- **Save an existing platform CSV to the current workspace.** Successful delivery returns an openable local file link for further inspection and analysis.
- **Preserve the original file content.** Delivery verifies size, encoding and digest without recalculating business data or changing CSV bytes.
- **Stay within the current session's authorization.** Read-only sessions, cross-session requests, path escapes, file conflicts and invalid content are refused. The current per-file limit is 512 KiB.

## 4. Interface and diagnostics

- **Complete more of the Chinese and English interface.** Plugin copy follows the DSH language setting across the panel, configuration, login, diagnostics and provenance. Business names, original identifiers and model answers remain verbatim.
- **Improve keyboard access and dark-theme readability.** Refine dialog focus, Tab navigation, Escape dismissal and focus restoration, and improve the readability of body text and close controls.
- **Keep diagnostics accessible when the business component fails.** Retain panel guidance and the independent diagnostics entry instead of leaving an unusable empty interface after a business-module import failure.
- **Stop related reads when the provenance dialog closes.** Propagate cancellation to actual requests, reducing continued waits or state updates for a dismissed view.

## 5. Newer DSH versions and installation

- **Relax version-based loading restrictions.** DSH `0.2.1-rc.3` and newer versions may attempt loading instead of being rejected solely by a fixed upper version limit.
- **Add DSH `0.2.1-rc.5` verification.** Official Windows Desktop installation, actual component loading and the specified diagnostic fault scenario were checked. This does not establish complete functional acceptance on the newer version.
- **Ship MCP connection protections with the plugin.** No separate profile companion installation or official DSH replacement is required.
- **Retain access governance.** Wider loading admission does not relax knowledge-network, session, permission or dependency-instance identity checks.

## Usage and upgrade

Install or update through DSH plugin management:

```text
@openbkn/dsh-business-context@latest
```

To pin this release, use:

```text
@openbkn/dsh-business-context@0.2.1-rc.3-openbkn.0.2.1-2
```

Continue using standard mode for business sessions. Automatic authorization requires a compatible OpenBKN CLI and Chrome or Edge installed locally.

**Private-platform trust boundary:** This revision automatically observes and pins the platform certificate fingerprint in place of public CA and hostname identity verification. First contact does not provide public-PKI identity assurance. Certificate validity dates, platform identity binding and cross-origin restrictions remain enforced; system-wide trust is unchanged. This is the accepted private-environment trust policy, rather than the earlier manual CA-import approach that retained all public-PKI checks.

## Verification and known limitations

- Final build CI passed: 657 plugin tests and 79 repository checks, with one Windows-only test skipped in that environment. Affected Mac and Windows validation and existing evidence are reused within their recorded scopes; this documentation update does not rerun those checks.
- Permission to load newer DSH versions is not a promise of full compatibility with every future version. Installation, component loading, real business Q&A and human acceptance are recorded separately. Strict npm/pnpm peer policies may still warn or reject other prereleases, and each DSH version's own Node requirements still apply.
- In the normal Windows DSH `0.2.1-rc.5` instance, diagnostic-export clicks produced no observed dialog or file; the cause remains untriaged. Export succeeded in the fault instance, which does not establish success in every scenario.
- Neutral guidance and independent diagnostics under a business-import failure passed controlled checks. The actual Remote rejection brand, code and call phase, and a regression matching that observed error shape, remain unconfirmed. Issue #63 closed under the maintainer's revised criterion, without claiming that the missing evidence was collected.
- Owned authorization browser profiles and superseded authorization-generation directories remain on disk. Platform-discovery and connection TLS handshakes each have an independent five-second bound that does not increase with the request timeout.
- Native provenance depends on platform routes, account permissions and available records. Existing-record read and linkage verification does not establish correctness for every new model answer or complex business question. Historical failures, blocked cases and unknowns retain their original verdicts.
- The plugin handles authentication, access governance, file delivery and provenance presentation. OpenBKN supplies business calculations and platform states; the model generates natural-language answers. The plugin does not arbitrate answers, add automatic corrective turns or rewrite platform and model output.
