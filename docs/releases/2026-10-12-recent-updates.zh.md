# bkn-dsh 近期更新说明

[English](2026-10-12-recent-updates.md)

**汇总范围：2026 年 9 月 21 日至 10 月 12 日**  
**当前已发布版本：插件 -9**（`@openbkn/dsh-business-context@0.2.0-rc.2-openbkn.0.2.0-9`）  
**当前支持的 DSH 版本：0.2.0-rc.2**，支持官方桌面版、npm 命令行及源码构建宿主。

本文汇总近三周已合入主线的更新，包含多个插件版本的累计变化。

这轮更新完善了从安装、配置、登录到业务问答、溯源与问题诊断的使用流程。普通用户可以在 DSH 内完成主要设置，直接使用授权的业务知识网络，并查看回答涉及的执行过程和业务来源。

## 一、安装与首次使用

- **直接安装到官方 DSH。** 安装插件即可使用，无需另外下载 OpenBKN Runtime 或给宿主打运行补丁；独立 Runtime 归档停止更新。
- **新增面板内配置。** 在 OpenBKN 面板填写平台地址，通过“保存并继续”应用设置；高级设置支持指定 CLI 路径，无需手动编辑 YAML。
- **未配置时也能正常启用。** 新安装的插件显示待配置状态，用户可进入设置或诊断，不会因为尚未填写地址就无法打开入口。
- **新增 CLI 检测与安装。** 自动检查已有 CLI、显示版本和可执行路径；未找到时，可点击“检测并安装 CLI”，查看安装、验证进度和失败原因。检测到已有可用版本时予以保留。
- **配置错误提示更明确。** 非法平台地址、目录被误填为可执行文件、CLI 缺失等情况分别给出处理指引；无效提交不会覆盖已有设置。

## 二、登录与连接恢复

- **首次登录流程更顺畅。** 修复从未登录或无法确认凭据过期时间时，被错误提示为“无法验证连接”的问题。
- **支持面板内重新登录。** 凭据被拒后，可使用“使用 OpenBKN CLI 登录并同步”入口，在浏览器完成授权后回到 DSH 继续操作，无需粘贴 Token。
- **错误提示按原因区分。** 登录失效、权限不足、证书、网络及未知连接故障分别提供指引，减少把所有连接问题都归因于账号或平台地址的情况。
- **配置切换更稳妥。** 平台地址变更后，诊断观察随之更新；已有会话保留原平台与知识网络绑定。关闭、重开或重载面板后，旧请求不会重新打开面板或覆盖新状态。

## 三、知识网络与业务会话

- **会话绑定可在官方桌面版恢复。** 网络绑定独立、原子保存；重开会话时恢复绑定与业务会话续接信息，并支持读取历史会话记录。
- **并发绑定更可靠。** 同一会话同时绑定不同网络时，明确报告冲突；同一网络的重复绑定保持一致，失败后允许重试。
- **访问范围检查更完整。** 直接调用平台工具时，检查知识网络参数，拒绝缺失、类型错误或跨网络的请求；未绑定会话无法直接使用 OpenBKN 业务工具。
- **减少无意义的执行记录。** 闲聊、澄清及无需访问平台的问题不会额外创建业务 Interaction；需要访问业务知识的回合才进入受控执行流程。
- **业务能力发现与调用更准确。** 根据实际可用工具和能力生成调用指引，对不支持的工具明确说明原因。
- **保留 DSH 原生回答。** 问答使用模型原生输出，插件保留业务上下文、访问治理与溯源，不再插入自动纠错回合或强制固定的 BOM、库存回答格式。
- **标准模式指引更清楚。** 面板明确提示业务会话使用标准模式；误用 PTC 模式时给出切换指引。

## 四、业务溯源与证据查看

- **重构为分层溯源。** 每轮回答可查看本地执行时间线、平台操作、业务上下文图与证据链。时间线展示调用顺序、耗时与状态，连续同类调用可折叠查看。
- **各视图独立处理异常。** 平台记录无法读取时，本地时间线仍可展示；区分未授权、记录未披露、记录过大和暂时不可用。
- **支持更大的平台操作记录。** 原始响应读取上限提升至 64 MB，减少长业务回合无法展示操作记录的问题；超过上限时给出明确提示。
- **修复业务元素来源定位。** 根据平台披露的引用逐项识别来源知识网络，避免混合网络数据被错误归到同一来源。
- **证据链提供查询指引。** 展示平台回执，并提供可复制的 CLI 查询命令，便于继续核查具体操作。

## 五、诊断与问题处理

- **新增统一诊断入口。** 在 OpenBKN 面板右上角打开诊断，查看组件加载、配置、CLI、登录和平台请求状态。
- **业务组件故障时仍能定位问题。** 业务配置、导入或初始化失败时，独立诊断入口仍可提供信息；整包公共文件损坏仍需重装处理。
- **故障分类更细。** 区分配置、CLI、认证、权限、TLS、网络和响应解析等问题；无法判断时明确显示证据不足。
- **支持导出诊断报告。** 将允许导出的检查信息整理为 JSON，便于交给管理员排查，报告保留必要状态并排除凭据等敏感内容。
- **观察结果更准确。** 不同接口独立记录成功与失败，恢复后保留历史失败线索。“重新采集”刷新已观察状态，不主动发起完整重连测试。

## 六、跨平台、文档与交付

- **改进 Windows CLI 查找。** 按 Windows 的可执行文件解析规则识别 `openbkn.cmd` 等入口，修复默认配置下找不到 CLI 的问题。
- **改进工作区选择提示。** 打开系统目录选择器时提示用户到系统窗口完成操作；取消选择可正常返回，真实故障按原因报告。
- **补充中英文图文手册。** 使用供应链样例及带点击标注的实机截图，覆盖安装配置、登录、知识网络选择、业务问答、溯源和诊断；提供离线 HTML 与中文 PDF。
- **完善发布与核验。** npm 发布附带来源证明，发布插件时同步生成 GitHub Release；加强包导出检查、跨平台验证与发布产物核对。

## 使用与升级提示

- 在 DSH 插件页面安装或更新 `@openbkn/dsh-business-context@latest`，完成配置与登录后，在标准模式会话中使用。
- 卸载插件保留用户配置、凭据、工作区和会话数据；独立安装的 CLI 也会保留。
- 若重新登录成功后仍持续拒绝业务调用，可重启 DSH，再进入原会话重试。该偶发问题的根因尚未确定。
- Windows 卸载时若出现 `pnpm-lock.yaml` 的 `EPERM` 错误，可重试移除，并确认插件包已删除。
- 深层 BOM、库存等较长查询仍可能超时；本轮不宣称所有复杂业务问答均已解决。平台端脚本或技能内部的调用也不经过插件的直接工具范围检查。
