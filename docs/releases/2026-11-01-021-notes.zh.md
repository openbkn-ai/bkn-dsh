# bkn-dsh 0.2.1 发布说明

[English](2026-11-01-021-notes.md)

**当前发布版本：** `@openbkn/dsh-business-context@0.2.1-rc.3-openbkn.0.2.1-2`

**发布状态（截至 2026 年 11 月 1 日）：** 已正式发布，npm `latest` 和 `rc` 均已指向该版本。本文汇总 0.2.1 基础版及 -1/-2 两次修订，不代表所有功能都在 -2 中新增。

本次更新重点完善登录体验、业务溯源与跨视图联动，新增 CSV 文件交付，并放宽新版 DSH 的加载限制。用户可以在 OpenBKN 面板发起授权、查看登录结果，再进入知识网络开展业务问答。

## 一、登录与连接恢复

- **私有平台登录无需手工配置 CA。** 从面板发起 CLI 登录，在独立的 Chrome 或 Edge 浏览器配置中完成官方账号授权，无需修改 shell 配置或系统全局证书信任。
- **登录结果直接显示在当前面板。** 授权成功并验证凭据后，面板自动显示结果及可访问的知识网络，修复已完成授权却仍停留在等待状态的问题。
- **平台身份变化后重新授权。** 平台地址、观察到的 IP 或证书发生变化时，要求重新完成浏览器授权；普通访问令牌到期仍由官方 CLI 续期。
- **统一覆盖后续业务连接。** 登录、MCP、知识网络目录及溯源读取使用对应的授权身份，防止旧连接把已有凭据发送给新授权的平台身份。

## 二、业务溯源与证据查看

- **增加平台原生溯源展示。** 通过事件链、证据链及业务上下文，查看回答涉及的执行步骤、输入、处理过程、来源与结论。
- **完善跨视图选择联动。** 选择执行步骤、来源或证据节点时，根据平台披露的关系定位关联内容，减少在多个视图之间反复查找。
- **修复共享输入造成的跨分支误联。** 选择某条查询时，保留该分支的关联范围；选择两条查询共用的输入时，仍可同时查看两条查询。
- **更准确地展示缺失和异常状态。** 区分未生成、未记录、权限不足、暂时不可用及部分结果；可用的本地执行时间线继续保留。
- **忠实保留平台记录。** `invalid` 状态及原因按平台原文展示，原记录继续保留，插件不重新判定其有效性，也不补造证据关系。

## 三、CSV 文件交付

- **支持将平台已有 CSV 保存到当前工作区。** 导出成功后返回可打开的本地文件链接，方便继续查看和分析。
- **保留原始文件内容。** 交付过程校验文件大小、编码和摘要，不重新计算业务数据或修改 CSV 字节。
- **限制在当前会话授权范围内。** 只读会话、跨会话请求、路径越界、文件冲突及无效内容会被拒绝；当前单文件上限为 512 KiB。

## 四、界面与诊断体验

- **完善中英文界面。** 插件文案跟随 DSH 语言设置，覆盖面板、配置、登录、诊断及溯源；业务名称、原始标识和模型回答保留原文。
- **改善键盘操作和深色主题显示。** 完善弹窗焦点、Tab 导航、Escape 关闭及关闭后的焦点恢复，提高正文和关闭按钮的可读性。
- **业务组件失败时仍可查看诊断。** 保留面板提示和独立诊断入口，避免业务模块导入失败后只剩无法操作的空界面。
- **关闭溯源窗口时停止相关读取。** 取消操作向实际请求传递，减少已关闭视图继续等待或更新状态的问题。

## 五、新版 DSH 适配与安装

- **放宽版本加载限制。** DSH `0.2.1-rc.3` 及更高版本允许尝试加载，不再因固定版本上限直接拒绝。
- **补充 DSH `0.2.1-rc.5` 验证。** 已完成 Windows 官方桌面版安装、实际组件加载及指定诊断故障场景检查；这不代表所有功能均已完成新版验收。
- **MCP 连接保护随插件交付。** 无需再手工安装独立的 profile companion，也无需替换官方 DSH。
- **保留访问治理。** 放宽版本准入不会放宽知识网络、会话、权限及依赖实例一致性检查。

## 使用与升级提示

在 DSH 的插件管理中安装或更新：

```text
@openbkn/dsh-business-context@latest
```

需要固定本次版本时使用：

```text
@openbkn/dsh-business-context@0.2.1-rc.3-openbkn.0.2.1-2
```

业务会话继续使用标准模式。自动授权需要本机已有兼容的 OpenBKN CLI，以及 Chrome 或 Edge。

**私有平台信任边界：** 本版自动观察并绑定平台证书指纹，以此替代公共 CA 和主机名身份验证；首次连接不具备公共 PKI 的身份保证。证书有效期、平台身份绑定和跨源限制仍保留，系统全局信任不变。这是已接受的私有环境信任策略，并非保留全部公共 PKI 校验的手工 CA 导入方案。

## 验证与已知限制

- 最终构建 CI 通过：657 项插件测试、79 项仓库检查，另有 1 项 Windows 专用测试在该环境跳过。Mac、Windows 的受影响场景验证与既有证据按各自范围复用；本次文档更新不重跑这些检查。
- 允许新版 DSH 加载，不等于承诺所有后续版本均完整兼容；安装、组件加载、真实业务问答和人工验收分别记录。npm/pnpm 的严格 peer 规则仍可能对其他预发布版本给出警告或拒绝，各 DSH 版本自身的 Node 要求仍适用。
- Windows DSH `0.2.1-rc.5` 正常实例中曾观察到点击诊断导出后未出现对话框或文件，原因尚未确定；故障实例的导出成功，不能据此宣称所有场景均已解决。
- 业务组件导入失败时的中性提示和独立诊断已通过受控检查；真实 Remote 拒绝的品牌、代码和调用阶段，以及对应实际错误形态的回归仍未确认。#63 按维护者调整后的标准收口，不代表这些证据已补齐。
- 独立授权浏览器配置及被替代的授权代次目录会保留在磁盘上。平台发现与连接的 TLS 握手各有独立的 5 秒限制，不随请求超时一并延长。
- 原生溯源取决于平台接口、账号权限及实际记录。已有记录的读取与联动验证，不代表所有新模型回答或复杂业务问题均已通过；历史失败、受阻和未知项保留原结论。
- 插件负责认证、访问治理、文件交付和溯源展示。业务计算与平台状态由 OpenBKN 提供，自然语言回答由模型生成；插件不仲裁答案、不自动纠错，也不改写平台和模型输出。
