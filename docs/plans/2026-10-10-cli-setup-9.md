# -9 CLI 设置最小开发计划

范围由用户明确限定：CLI 检测、自动安装、状态提示；完成 Mac 实测后提交 PR，并给 Windows 独立复测 handoff。发布不在本次授权范围内。

1. 在现有高级设置内接入只读检测。优先当前 Host PATH，然后有界常见目录和 npm 全局 prefix；必须真正执行 `--version`，不能以文件存在或安装退出码代替可用。
2. 显式按钮“检测并安装 CLI”重新检测，仅默认 `openbkn` 未检测到且 Node/npm/prefix 均满足条件时安装固定 SDK 0.1.5。自定义路径、损坏的已有安装与权限问题给出提示，不自动覆盖、升级、提权或修改 PATH。
3. 展示真实检测/安装/验证状态，不虚构进度。Host 只回传受控字段，保留安装源设置，不向 Client 回传 npm 原文。检测到的路径填入表单草稿，仍由原生 ConfigEditor 保存。
4. 每个 Host 同时只接受一次安装；关闭面板不取消已启动 npm，卸载/关闭 Host 按原生 subprocess 生命周期清理。重开面板可检测仍在进行的安装。登录、凭据与业务语义完全沿用 -8。
5. Host/helper 与 UI 生命周期测试覆盖已有可用、PATH 之外、真正缺失、损坏安装、自定义路径、前置条件、权限/网络/证书错误、退出 0 但验证失败、重复点击与关闭面板。跑项目规定的构建/类型/插件/仓库/打包检查。
6. 构建并固定 build-only CI 候选；在 Mac 官方 npm 和 Desktop 上用隔离 DSH_HOME、BKN_CONFIG_DIR、npm prefix/cache 实测，保留真实安装与受控故障的区别。核对日常 profile 内容哈希，归档本轮进程清理证据。
7. Mac 验收后提交英文 PR，写可执行 Windows handoff，固定 source/CI/tgz SHA/文件清单/获取方法。Windows 使用原生 PowerShell 和隔离全局 prefix，禁止借用日常 CLI/store，禁止发布。

暂不做：DSH/Node 版本迁移、跨平台安装管理器、系统 PATH 修补、自动重启、自动升级/卸载 SDK、Token 管理、平台业务校验、模型回答治理、旧版升级矩阵与历史故障根因修复。
