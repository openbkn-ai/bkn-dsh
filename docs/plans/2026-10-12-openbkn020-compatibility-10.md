## 最小开发顺序

| 顺序 | 改动 | 完成条件 |
|---|---|---|
| D1 | CLI 安装版本与提示 | 沿用检测/安装入口，明确支持 0.1.5 和 0.2.0 两个固定安装目标；安装目标与验证版本一致；既有 CLI 显示实际版本；版本不匹配引导使用匹配 CLI |
| D2 | 导航摘要解析 | 合法 `null` 概念数组不再误报响应非法；保留网络身份验证、概念组及可用数量；没有返回索引时不显示成“零对象/零关系” |
| D3 | Trace 降级最小复现及适配 | 先由当前生产路径复现 `trace_recorded:false`，再识别禁用/不可用结果；业务访问仍受会话、网络和工具边界约束，溯源如实降级 |
| D4 | 契约/测试/文档收口 | 新 fixture 独立来自固定上游源码；更新受影响 prompt、CLI 文案、README 与 changelog；保留 0.1.5 路径，不扩大工具权限 |

### D1：CLI

最小方案不做自动平台版本探测或通用多版本管理：仅在现有安装入口明确选择目标平台对应的固定 SDK 版本，传给 Host 的值限制为 `0.1.5` / `0.2.0`。该选择只是安装参数，不增加凭据或平台配置体系。不能从 URL 猜版本，也不能将未知版本默认为“兼容”。

保留现有“检测到已有 CLI 就不覆盖”的保护。已有版本不适用时说明原因并引导配置匹配 CLI 的路径或由用户自行更新；不让安装按钮静默替换日常 CLI。缺失时，用户显式安装所选版本，继续复用 npm、prefix、超时、单次安装与进度/锁定逻辑。0.2.0 包尚未正式可获取时不把真实 npm 安装标为通过，也不装准备源码冒充正式 SDK。

预期涉及 `cli-setup.ts`、`configuration-service.ts`、CLI setup 类型/控制器/组件及文案。只传固定版本枚举，不接受任意包名、版本字符串或 shell 命令。

### D2：导航摘要

按明确的新响应分支接受对象类 >200 或关系类 >600 的导航摘要，仍核对返回 `id` 与绑定网络。区分完整数组、合法导航摘要、非法/缺失结构；不能用普遍 `null -> []` 容错吞掉非法响应。保留可选 profile 失败时不阻止已核验绑定的原行为。

不为了获取旧全量摘要而遍历全部对象类；查询按平台公开 schema 工具按需执行。上游输出 Schema 的 nullable 不一致独立交平台处理，插件不伪造返回数据。

### D3：Trace

正常 start/finish 保持原路径。对平台明确返回的 `trace_recorded:false` / `capture_enabled:false` / `trace_available:false` 增加最小状态表达：没有本轮 Interaction ID 时不伪造或复用旧 ID；旧持久 Conversation 是否保留按平台身份事实处理，不能把“本轮未记录”直接等同于“旧 Conversation 已失效”。

禁止仅因无 ID、未知返回、鉴权错误或网络错误就自动放宽 guard。降级也不能绕过绑定网络校验、未知工具拒绝和单回合边界。继续业务查询，不为补 Trace 重跑已完成业务请求；正常溯源与未记录/不可用状态分别显示。

`partial_reasons` 只在确认 DSH 透传对应 Trace 元数据后做必要接线；不得猜造原因或引入独立证据账本。若宿主未透传，明确记录限制与是否阻塞，不能宣称完整证据链。不得把这项视为 B1 token 问题的根因或修复。

## 正式 0.2.0 发布后实机门槛

2026-10-12 后续用户调整：允许使用另一会话从 `release/0.2.0` 构建的 SDK，并要求 Mac / Windows 只验证 -10 变化。实际执行范围以 [最小验收计划](2026-10-12-compatibility10-minimal-acceptance.md) 为准；下列原完整矩阵保留为历史计划，不再要求本轮全量重跑。

这里的“正式包”指正式 OpenBKN 0.2.0 平台版本/镜像及 npm SDK；它们到位后验收 -10 build-only 候选，完成验收后再决定发布插件 -10。

1. 固定正式 tag/commit、各服务镜像、SDK npm 包及 SHA，复核相对开发期契约的变化与上游 nullable 修正状态。发生影响插件的差异时先更新代码/测试/候选。
2. Mac 官方 npm 与 desktop 使用同一新候选：首次配置、对应 CLI 安装/登录/同步、列网绑定、正常查询、已发布能力、来源图/回执、诊断与真实导出。
3. 同两形态验证大网络导航摘要，以及平台可构造的 Trace 禁用/不可用分支。不能构造的项如实 not-run，不拿旧平台或纯 mock 充当实机验收。
4. 按支持承诺做 0.1.5 受影响回归；Mac 通过后，将 Windows 两形态范围、固定版本/SHA/获取方式、原件归档与收态要求单独提交 handoff。
5. Windows 回传复核、候选身份一致后才进入主线构建/发布门禁。B1 未复现则继续写已知开放项，不宣称修复；正式发布另按用户授权执行。

实机护栏：使用隔离 DSH/CLI 配置和测试工作区，开测前/结束后记录保护文件哈希；启动及停止留存 owned PID 身份证据；报告脱敏并核对下载原件与 Git blob；不改日常 CLI、PATH、平台数据或模型配置。
