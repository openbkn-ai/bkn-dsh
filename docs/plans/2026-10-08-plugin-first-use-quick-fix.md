# 插件首次使用快速修复与后续完善计划

日期：2026-10-08。状态：A0–A5 源码实现与本地检查已完成；A0 官方 npm Host 的原生配置保存/重载预验已完成。固定 CI 候选、界面及真实连接验收进行中，尚未发布。首批目标是让用户完成“安装/启用 → 填写地址 → 登录 → 选择知识网络 → 提问”，并能正常关闭面板、诊断和卸载。

## 基线与范围

- 本地源码与远端 main 均为 `4995109330a800060c523509cdaca8403744cd86`；编写前工作树干净。
- 本轮查询官方 npm：`latest`、`rc` 均指向 `0.2.0-rc.2-openbkn.0.2.0-7`，版本列表没有 `-8`；远端也没有对应 `-8` tag。首批暂定 `0.2.0-rc.2-openbkn.0.2.0-8`，发版前再次核对。
- 受支持的 DSH pin 保持 `dsh-v0.2.0-rc.2`；实施前按仓库规则刷新 DSH、OpenBKN/CLI 的上游和实际部署基线，不自动升级 pin。
- 用户已确认“latest 安装后显示 -4”是 npm 本地缓存问题；本轮移出排查范围。
- 保留三入口隔离、原生模型回答、网络范围治理、Interaction、诊断和溯源。首批不开发新的 Runtime、配置存储、OAuth 实现或业务答案裁判。

### 实现边界与主要文件

- `src/config.ts`、`src/business.ts`：待配置值与业务挂载边界。优先保留 `baseUrl` 的字符串类型和默认空值，在开始业务工作前完成配置判断，避免把可选地址传播到所有请求实现。
- 新增最小配置 Remote 服务：限定编辑本包业务条目的 `baseUrl`/`cliPath`，调用 DSH 编辑器保存；不开放任意条目、路径或 YAML 写入。由现有独立入口承载，保持诊断报告方法只读；不能把配置调用放进正在被重载的业务服务里而忽略调用生命周期。
- `src/diagnostics.ts`、`src/diagnostics-service.ts` 及必要契约：配置服务使用可选的宿主能力注入，不能使配置编辑器缺失也拖垮诊断。保留根 bootstrap 的零导入和 business/diagnostics 互不可达约束；不增加第四个 row。
- `src/types.ts`：新增配置 DTO 仍从 `./types` 面归属，遵循既有 typert 生成约束。配置值仅给设置界面使用，诊断继续输出有限分类和布尔证据。
- `src/client/OpenBknOverlay.tsx`、`openbkn-ui-controller.ts`、`openbkn-panel-bridge.ts`、`index.tsx`：复用现有面板和控制器，增加待配置/保存状态、一个表单和旧请求失效保护。
- 保存只改指定字段，保留其他高级配置；更高层 patch/启动参数覆盖时准确报告无法生效。禁止用自写 YAML 文件绕过 DSH 的锁、校验、原子写入与重载。
- 地址改变后旧平台的检查终态失效；新平台尚未检查时不得继承旧平台的 pass。相同地址的 401 → 重登恢复仍保留既有恢复历史。
- 对缺失、关闭或损坏的业务服务继续明确降级，保留诊断；不宣称可以在任意损坏的宿主中修改配置。
- 既有标准模式、未绑定/跨网拒绝及溯源行为保持；不借本轮重写会话或问答系统。

- 保留原生输出、产品导出、配置哈希、包身份及进程收态；不把受控探针当作真实登录或 Windows UI 验收。

### 交付顺序

1. 在功能分支完成 A0–A5、对应测试和新的用户安装说明；commit/PR 内容使用英文。
2. 提交 PR 评审，修完后运行 `release-plugin.yml` 的 `publish=false` 彩排，固定 commit、tgz SHA 和逐文件清单。
3. macOS 与 Windows 均使用这一 CI 包验证。Windows handoff 连同获取方式提交远端，使用隔离环境，不动用户日常配置。
4. 汇总结果和仍开放项；验收后有包内容变化则重出候选并重跑受影响项。合并后 main 彩排包必须与验收包一致。
5. 按现有发布门禁发布新版本，保留 -7 不变。公开包核验后迁移 `latest`，再用官方源/大陆镜像的真实 `@latest` 做新安装冒烟；候选验证的固定包路径只用于开发取证。

首批停止扩展的条件：用户可以不改 YAML 完成配置和真实登录、进入业务会话；关闭与错误恢复可靠；包隔离、治理和卸载无回归；声称支持的形态有候选验收证据。
