## 最小矩阵

| 项 | 范围 | 判定与最小证据 |
|---|---|---|
| M0 身份 | 每个安装形态 | 固定候选、安装后 70 文件、SDK 版本与包 SHA；每个操作系统只采一次平台契约 |
| M1 诊断展示 | desktop / npm | Mac 展示 macOS、Windows 展示 Windows；未采集/未识别解释准确；磁盘与已加载版本区分；每形态一份真实产品导出 |
| M2 CLI 0.2.0 | desktop / npm | 安装目标初始未选择；选择 0.2.0；现有隔离 CLI 被识别并可保存使用；不改日常 CLI；npm 未发布时不把本地包识别当成自动安装验收 |
| M3 正常链 | 每个操作系统一次 | CLI/插件连接及列网，固定网络的受管 start → 一次只读查询/能力 → finish；记录来源或明确降级；允许直接调用官方 DSH 工具运行时，注明无模型，不评估答案质量 |
| M4 变化分支 | 每个操作系统一次 | 固定候选的导航摘要解析、Trace 禁用/不可用、成功 finish 后访问关闭受控探针；存在可读大网络或自然降级时加一次实机观察，否则实机项 not-run；不为构造场景修改平台数据/开关 |
| M5 短流程凭据同步回归 | 每个操作系统一次 | 正常连接后同进程重新同步凭据并新建受管轮次；记录是否拒绝及耗时。这不是历史 B1 的复现，B1 根因仍未知；不延伸为旧长时运行问题已修复，不做 8 小时 soak，也不将长时复现设为每版门槛 |
| M6 收态 | 每个操作系统一次 | 选定日常文件开测前/结束后内容哈希；本轮 Host PID/创建时间/可执行文件/监听核验；保留下载来源及原件 SHA |

M3/M4/M5 的进程边界探针与完整 UI Host/模型问答分别标注，不能混称。历史源码/受控测试继续作为既有证据，不重复全套测试；发生新缺陷或源码变化才更新候选并复验受影响项。

## 交付与发布边界

Mac 结果与实际限制先固定，再提交独立 Windows handoff（同候选、同 SDK、最小矩阵、获取方式、原件和收态要求）。Windows 回传复核后进行主线 build-only 与包一致性门禁；正式发布另按用户授权执行。
