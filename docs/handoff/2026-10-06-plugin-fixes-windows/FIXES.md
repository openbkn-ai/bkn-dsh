# -7 受影响验收追加项

## F01：来源知识网络（#62）

在已绑定网络的标准模式中完成一次真实业务问答，从该回答打开“查看业务溯源”→“业务上下文图”。选择物料、库存、指标等至少两个正式元素，记录平台授权业务图中对应 technical_ref 的 ref_type/ref_id 与界面来源。规范例：object:<kn_id>:<object_type_id>、metric:<kn_id>:<metric_id>、kn:<kn_id>；界面应显示该元素引用披露的 kn_id。

只读取账号有权查看的 business-graph。未披露、非法/未知引用应保持“未定位”；不得按当前绑定、对象名称或模型文本猜测来源。多网络 Operation 若真实可取得，逐元素核对各自来源，不能取第一条覆盖其余；取不到记 not-run。开发用例已覆盖混合网络与未知引用，不能冒充 Windows 实机混合网络证据。

## F02：业务故障提示（#63）

使用 W3 的同一固定 -7 CI 包故障变体，仅破坏 exports['./business'] 的业务导入。侧栏只保留 OpenBKN；外框右上角“诊断”可打开，business-entry 应为 module-resolution-failed。未知连接/RPC 提示应说明原因尚未确定并引导诊断/导出，不再无依据提示“检查 Token 和平台地址”。

另看 W2 配置失败与 W4 初始化失败的提示及报告。保留原候选 SHA；故障变体另记基包 SHA、修改文件及前后哈希。已知缺 CLI、真实 401/403 与平台不可用仍应显示相应原因，不以所有错误同一句话代替分类。

使用 history/ 内旧 CI -6 先安装，设置非默认 baseUrl/cliPath 或其他无敏感 canary，确认原三 row 与配置生效。用固定 -7 升级，记录配置保留、仍为三 row、无重复侧栏入口；重复安装 -7 保持幂等。-4/-5 的两 row→三 row 与 name-qualified 迁移仍按 MIGRATION.md 验证。

## 调查项与限制

U01 记录首次/重复/移除重装的实际启动及设置读取结果；未复现不等于历史偶发 RPC 根因已定位。U02 分开记录首次未登录、真实有效、真实过期可续期与真实不可续期；只保留布尔状态与退出码，Token 不进入回传。当前插件未实现自动续期；Mac 已证实正常 CLI 手动续期后同进程恢复。没有真实过期/不可续期状态时记未测，不撤销主账号授权制造场景。Q01 保留原 missing-object 规则，评判新回答，不把前文里的数字算作当前回答违规。
