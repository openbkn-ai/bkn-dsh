- ☑ 2.2 绑定记录孤儿清理：会话删除后，记录跟着清除。原因：评审提出的已知限制；用户决定放进本次发版。（本地提交 `93ff5f9`，未推送）
  - DSH 0.2.0-rc.2 没有删除会话的接口（`SessionPersistence` 只有 create/open/flush/stat/list），只有归档；所以孤儿记录只会出现在会话文件被 DSH 之外删掉的时候。
  - 实现：`sessionPersistence` 可用时，启动扫描一次（`ctx.inject`）。满足以下全部条件才删：
    - 记录写入超过 7 天；
    - 本进程 `stat(id)` 返回不存在。
  - 另外三种情况一律保留：格式错误的记录、`stat` 出错的记录、7 天内的记录。原因是 JSONL 会话是懒写入的，没写入第一条事件前，只有创建它的进程能看到。
  - 测试 229/229。桌面实测：7 天前的孤儿记录在启动时被删除，昨天的对照记录保留。
- ☑ 2.3 PTC 模式下，绑定会话拿不到 OpenBKN 数据。**用户决定：本次走方案 A（只支持标准模式，PTC 明确拒绝并提示切换）**，保证发布时间；PTC 支持留到后续版本。（本地提交 `6c56b78`，未推送）

    - 新增提示词段 `openbkn:ptc-unsupported`（order 519），每轮组装时按 `tools.get('run_code', agent)` 判断；在 PTC 会话里让模型不调用任何工具，直接告诉用户切换，其他模式下为空，不渲染。
    - 测试 230/230。
  - 桌面实测（`release/plugin-fix/…tgz`，sha256 `394536130b44bf9f9b6ae7c59ac48dc61ee6dacb93f860d8c971ba99d1be09e6`，终端注入 CA 启动）：
    - 默认 PTC 模式下提问，1 轮 1 步，3 秒内回答"当前是 PTC 模式……请新开会话并在发送第一条消息前选择「标准模式」"；
    - 日志 22 条事件，`tool/call` 0 条，插件事件 0 条（截图 `docs/evidence/2026-09-30-desktop-08-ptc-refused.png`）。
    - 还原：profile 4 个文件和 `workspace.json` 从 `run4-before` 逐字节恢复；残留移入 `run4-artifacts/`；会话目录文件名与实验前一致；桌面版已重开。凭证审计：`.credentials.yaml` 在 14:49:38 被插件的 token 同步写过。
  - 后续版本做 PTC 支持时要解决的问题（评估记录，2026-09-30）：
    - `run_code` 的子调用会经过 guard（`scheduler.prepare`），也会触发 `tools/result`，所以网关规则和实时状态可以沿用；
    - 但日志记为 `tool/ptc-dispatch`（没有 `turn`，要通过 `parentCallId` 找到外层调用），交互重放、溯源、时间链三处读取都要改；

## Windows 验证步骤（交给用户安排的机器和 agent）

在 4.3 发布之后执行，以 README「安装并开始使用」为准。每一步记录命令输出或截图；不要把 Token 写进任何文件。

1. 准备：安装 Node.js ≥22.19、`npm install -g @openbkn/bkn-sdk`，执行 `openbkn auth login <平台地址>`。自签证书的平台，把 CA 路径设为用户环境变量 `NODE_EXTRA_CA_CERTS`（系统属性 → 环境变量），然后重新打开终端或应用。
2. npm 命令行形态：
   - `npm install -g @deepseek-ai/dsh@0.2.0-rc.2`，`dsh.cmd --version` 应输出 `0.2.0-rc.2`；
   - `dsh.cmd plugin --profile web add @openbkn/dsh-business-context@0.2.0-rc.2-openbkn.0.2.0-1`；
   - 在 `%USERPROFILE%\.dsh\profiles\web\cordis.patch.yml` 写入 baseUrl 条目（文件只有 `[]` 时整行替换）；
   - `dsh.cmd web` 启动，打开输出的地址。
3. 桌面版形态：
   - 安装 DeepSeek Harness 桌面版 `0.2.0-rc.2` 并启动一次，然后完全退出；
   - 用应用菜单「管理 dsh 命令…」把 `dsh` 加到 PATH，执行 `dsh.cmd plugin --profile desktop add @openbkn/dsh-business-context@0.2.0-rc.2-openbkn.0.2.0-1`；
   - 在 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml` 写入 baseUrl 条目。
4. 每种形态都做一遍：
   - 侧栏 OpenBKN → 选择 `supply_ontology_hand` → 新建工作区（Windows 原生目录选择器）→ 在**标准模式**的新会话里问「382-000005 有多少张销售订单？什么状态？」，期望 40 张、全部已确认；
   - 打开「查看业务溯源」；
   - 完全退出后重开，打开这个会话，追问「这些订单对应的客户有几家？」，期望 40 家；
   - 新建一个 PTC 模式会话提问，期望直接提示切换到标准模式、不调用工具；
   - 卸载插件（`dsh.cmd plugin --profile <p> remove @openbkn/dsh-business-context`）后重开，会话仍能打开。
5. 回传：每项的结果、`dsh.cmd --version`、插件版本（`dsh.cmd plugin --profile <p> list`），以及失败时的界面报错和 `%USERPROFILE%\.dsh\logs` 中相关片段（先去掉 Token 等敏感信息）。
