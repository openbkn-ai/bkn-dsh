**平台缺陷仍待维护者修复：[Issue #2029](https://github.com/openbkn-ai/bkn-foundry/issues/2029)，本轮只诊断和报告，不推进平台修改。**

最终 BOM 并非无异常运行：有被现有保护拒绝的 Bash 探查；深度 5 库存能力超时；模型还在 run_code 内再次尝试深层库存、提高脚本 timeout，未消除上游限制。其后才通过深度 1/2 校准仓范围、同资源只读 SELECT 聚合和完整内联表交付。这些偏离策略的动作均保留，不能宣称模型已完全遵守所有建议或所有工具调用都成功。

最终回退在 run_code 内调用了平台提供的 run_sql，只执行同库存资源、精确目标物料与仓过滤的 SELECT。它不是独立 CLI 对照路径，也不证明嵌套 SQL、权限或跨网 guard 已验收；这些保持单独范围。模型在沙箱保存了中间文件，但最终确实打印并内联交付全部 313 行，未依赖用户无法下载的沙箱附件。

早期 round2 的 event 探查把认证字段带进原始私有工具响应。交付文件已脱敏，私有会话/profile 未打包；新策略禁止该探查路径。应轮换当时的令牌，不能把该尝试当作推荐的回退方式。本轮仅作正常 CLI 登录有效性刷新，没有擅自更改账号权限或凭据。
