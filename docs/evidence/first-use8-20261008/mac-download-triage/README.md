# Chrome 当前上下文的诊断下载异常

用户手动点击以及自动操作均未在当时 Chrome 上下文取得诊断下载件。该观察保留为未定位的兼容性/环境异常，不直接归咎插件、浏览器或操作接口。

两次仅针对隔离安装目录的临时客户端探针显示导出函数已取得 3380 字节；延迟 30 秒释放 blob、改用 data URL 都没有产生已记录下载。第二次记录到真实用户激活、anchor click 且 `defaultPrevented=false`。因此没有证据支持将即时释放 blob 认定为根因，未据此修改源码。

探针均通过独立文件替换，随后恢复候选客户端原件（SHA-256 `5a60ee8d2137e65080b4445b3dc640cb96d00aa2815e521b325ec557e3d920f8`），固定包 66/66 重新核验一致。见本目录的身份与恢复记录。旧 Chrome tab 在恢复磁盘后仍可能缓存探针内容，不把该 tab 当成重新载入原候选后的证明。

恢复原候选后新建 IAB 上下文的产品导出实际下载成功：报告 `8ca4405a`，原件 `/Users/kalias/Downloads/OpenBKN-diagnostic-20261008T061908472Z-8ca4405a.json`；Desktop 原生保存对话框也完成产品下载。详细字节来源见相邻 `mac-ui/report-provenance.json`。这些成功限定于对应上下文，不能替代 Chrome 原异常的闭环。

没有改用户 Chrome 安全策略、系统证书信任、DSH 运行时或 -8 源码。正式发布前仍应明确处理此异常的验收边界。

Chrome 下载记录中只有旧报告 `4d141b89`，没有上述失败点击对应的报告；新的 S2 Chrome 上下文也没有记录报告 `98b95ece`。只读检查发现“下载前询问每个文件的保存位置”为开启。
