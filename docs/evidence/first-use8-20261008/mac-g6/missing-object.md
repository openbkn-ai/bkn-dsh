## 结论：知识网络中没有物料 999-999999

在 bound 的供应链本体知识网络 `supply_ontology_hand` 中，**不存在编码为 999-999999 的物料**，所以也没有可回报的库存与订单数据。

**核查结果（精确匹配）：**

| 对象 | 字段 | 命中 |
|---|---|---|
| 物料 material | material_code | 0 |
| 库存 inventory | material_code | 0 |
| 采购订单 po | material_number | 0 |
| 采购申请单 pr | material_number | 0 |
| 工厂生产计划 mps | material_number | 0 |
| 产品BOM bom | material_code | 0 |
| 销售订单 salesorder | product_code | 0 |
| 产品 product | material_number | 0 |

子串模糊匹配（like `999-` / `999999`）同样全部 0 命中，说明不是精确匹配写法的问题。

**检索有效性对照**（同一批查询返回，数据规模）：物料主档 3 497 条（编码形如 `101-000002`）、库存 19 724 条（`525-000025`）、采购订单 1 972 条（`725-000274`）；用同样的 like 方式查 `101-` / `525-` / `725-` 分别命中 3 / 513 / 210 条，证明模糊匹配链路正常。

**覆盖缺口（如实说明）：** `物料需求计划(mrp)` 没有可按物料编码过滤的属性（物料经关系 mrp2mat 建模），`监控证据明细(mon_item)` 与 `采购申请决策(pr_decision)` 未返回可查询属性，这三者无法按编码直接核验。结论仅对「编码等于 999-999999」成立。

**建议：** 请确认编码是否完整（该网络编码格式为 `3位-6位数字`）；若只记得名称/型号或部分编码，给我关键词，我按名称、型号做模糊检索定位；确定物料后我可以一并给出库存明细（库存量、可用量、预留量、仓库、批次）与订单全貌（采购订单、采购申请、生产计划、销售订单）。
