## rc.5继续执行时应保护的边界

1. 为已授权的rc.5隔离环境建立新的当前快照：实际EXE/ASAR、签名/build、PID+creation time、Host/端口owner、profile、Electron userData及URL关联。更新后签名或版本串不是候选安装/模块加载证据；仍需精确cf9ab包安装126文件、正常退出再冷启动及真实入口观察。
2. 回调实际进程必须同时核实隔离profile和隔离userData，不能只因继承DSH_HOME就认为完成隔离。另一独立源码审查负责回调实现；本报告不重复推导源码根因，也不把源码路径正确代替实际进程检查。
3. 保留原964队列两差异及默认userData未知Before的历史。新rc.5基线不能“重置为未改动”或掩盖旧差异；可只读比较有条件的结构变化，但不得以文件长度、mtime或单个hash推断内容语义。没有可信Before字节的文件不覆盖、删除或强制恢复；有Before也须核对当前所有者及期间新增的合法用户变化，防止回退新状态。
4. 协议关联目前观察为日常安装路径。不要为恢复旧检查点而盲改回已过时测试/rc.2路径；只对本轮受影响项使用Before/After/当前值守卫，避免全局注册表导入或覆盖受保护UserChoice。原日常实例的PID记录已是历史，清理前重新校验创建时间、归属和当前端口；不按进程名批量结束日常程序。

以上是继续执行的保全要求，不把历史根因未定改成新的全局暂停理由。当前授权允许修复/重建符合要求的隔离rc.5；未知字节不能靠强制回滚消除。当前rc.5准备及后续W1–W6结果应另留回执，明确接收方只核对公开报告及摘要、远程私有原件不在本机，也不声称完成全机/业务库审计。
