## 物料 999-999999：库存与订单情况

**结论：在本知识网络（供应链本体知识网络-手工版）里，这个物料编码没有查到任何数据**——主档、库存、采购申请、采购订单、销售订单五类全部为 0 行。

查询方式用的是网络里已发布的只读函数「物料库存与单据记录」，按确切编码 999-999999 一次性核查五类数据，函数返回 `exit_code=0`：

| 数据范围 | 匹配行数 | 说明 |
|---|---|---|
| 物料主档 (material) | 0 | 该编码不在物料主数据中 |
| 库存 (inventory) | 0 | 全仓、仅「可用」状态；可用量为 `null`（无记录，非实测 0） |
| 采购申请 (purchase_request) | 0 | 该编码无采购申请单据 |
| 采购订单 (purchase_order) | 0 | 该编码无采购订单单据（即无未结采购项） |
| 销售订单 (sales_order) | 0 | 该编码无销售订单 |

### 口径与限制
- **精确匹配**：五类数据只匹配 `999-999999` 这一个确切编码，不展开 BOM、不做全网对照，也不用编码区间去推断不存在。
- **库存口径**：全仓（`warehouse_scope=all`）、仅统计 `stock_status=可用`，不含在途；`available_inventory_qty` 已是可用量，不再二次扣减预留。无记录时函数返回 `null` 而不是 0，所以这里不能读作「库存为零」。
- **无法判断的原因**：可能是编码输入有误（例如少位/多位、格式不同），也可能是该物料确实未纳入本网络的演示数据。需要的话请确认真实物料编码，或告诉我物料名称，我按名称再查；若要确认全库是否存在相近编码，请明确授权我做一次编码模式检索（当前按函数规则未做全网对照）。
- 本次查询无需额外权限，函数返回的权限字段均为 `full`，没有权限提示。
