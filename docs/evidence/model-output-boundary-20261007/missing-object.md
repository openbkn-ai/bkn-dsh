## 结论：编码 999-999999 在知识网络中没有对应物料

按绑定的供应链本体知识网络（`supply_ontology_hand`）逐项核查，**库存和订单两路均为空**，且该编码在物料主数据里也不存在。

### 核查范围与结果

| 对象类 | 匹配字段 | 精确匹配 `999-999999` | 前缀 `^999-` |
|---|---|---|---|
| 物料 | material_code / material_name | 0 | 0 |
| 产品 | material_number / material_name | 0 | 0 |
| 库存 | material_code | 0 | 0 |
| 采购订单 | material_number | 0 | 0 |
| 采购申请单 | material_number | 0 | 0 |
| 物料需求计划 | materialplanid_number | 0 | 0 |
| 产品BOM | material_code | 0 | 0 |
| 销售订单 | product_code | 0 | 0 |

因为物料本身查不到，经 `物料→库存`、`物料→采购订单` 的关联路径也不会产生任何行。

### 现有编码形态（供核对是否写错）

- 物料编码形如 `101-000002`、`165-000081`、`725-000274`、`838-000318`（共 3497 条）
- 产品编码形如 `367-000061`、`382-000005`、`P61-000328`、`U00-000080`（共 30 条）

系统中不存在前缀为 `999` 的编码段，`999-999999` 看起来也不是本网络的合法编码规则。
