### 行为修正

- 登录调用完成后，必须再次得到 `authenticated` 才发布 `ready / succeeded`。`authentication-required` 或 `platform-mismatch` 保持需认证、标记失败并清空该次返回的目录；允许重试，取消后的迟到复查结果仍丢弃。
- `not_generated` 与 ready 一样按序列化后的 UTF-8 字节预算准入。合并后的 `native` 在逐项降级后再次检查大小；若连两个失败说明都容纳不下，完全省略 `native`，通过 `sources.degraded` 的 `pane: native / result-too-large` 明示原因，界面显示超限提示，本地时间线和历史视图仍保留。没有提高配置最小值或默认预算。
- 上述限额约束的是原生投影字段；整个 `ProvenanceView` 还包含本地/历史视图及降级元数据，不能把极小配置用例说成整个 Remote 响应仅有该字节数。
- 当前 Zod 的字符串 `.max()` 按 Unicode code point 计数，不能直接实现本合同的 UTF-16 单元上限；改用字符串 `.length` 显式检查。问答对图超过 64 项也统一归为 `result-too-large`，不误报结构无效。

## 执行步骤、来源与证据的跨视图联动

本轮按用户追加授权补齐 #97 的本地选择联动；没有扩大为 Studio 工作台、答案锚点、自动生成解释或平台写入。实现入口为 `src/client/native-provenance-selection.ts`、`NativeProvenancePanel.tsx` 和 `ProvenanceOverlay.tsx`。

### 选择与引用规则

- 事件、执行步骤、执行节点、结论、证据、业务定义来源和业务函数使用同一个带类型的选择标识；切换事件链/证据链及 zh/en 时保持选择，切换问答对或关闭后重开清除旧选择。即使两个问题复用 ID，也不会把旧选择带过去。
- 底色/`aria-pressed` 表示当前选中实体，描边/`data-related` 表示平台披露的关联。关联强调不把 candidate、partial 或未绑定状态升级为“证据已核实”，不替用户任选一个关联结论或业务函数作为主选择。
- 本地索引只使用 `claim.nodeIds`、`supportsClaimIds`、`executionNodeId`、输入 `sourceRef/evidenceRefs`、输出 `evidenceRefs/adoptedRowRefs`、`schemaRefs`、业务函数和关系记录的 `operationIds`、正式图端点及步骤的 `timeRailItemId`。按记录的上下游与相关业务函数的输入/输出/来源提供导航，不依据名称、数值或时间接近补关系，不生成或写回新的业务证据。
- 业务函数或关系记录只给 Operation ID 时，保留其操作级关联，可涉及多次尝试；选定某个具体事件或步骤时，只有 `timeRailItemId`、Operation ID、attempt 三项一致才关联到其精确事件，不通过相同 Operation ID 把另一次尝试高亮为当前尝试。
- 输入/输出/业务定义引用可点击进入证据链；步骤和证据节点的执行引用可进入事件链。引用切换只改变 Client 选择和标签，不重新读取平台，也不触发 POST 或工具调用。无法解析的外部/opaque 引用、缺失端点、冲突和歧义保留为文本及说明，不构造替代节点或外部链接。
- 标识带实体类型，跨类型同 ID 不混用；无类型图端点有多个候选时不猜类别。选定问答对的关系图不混入顶层另一套 evidence edges；没有问答对图时仍支持公开的顶层执行/证据关系。循环关系使用访问集合终止遍历。
- 事件关联多个业务函数时全部保留为关联，事件名称回退到其平台接口名并说明关联数量，不把第一个函数任意当成该事件的唯一业务名称。业务输入/处理/输出和原始状态继续按平台记录展示。
